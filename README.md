# CivicTrack Analytics – NIST Risk Management Framework (RMF) Project

## Project Overview

This repository documents my practical learning experience applying the **NIST Risk Management Framework (RMF)** through a scenario-based GRC project on GRC Playground.

The project uses a fictional organization, **CivicTrack Analytics**, and its internal incident analytics system hosted on AWS.

I completed all seven steps of the NIST RMF process, taking the role of a Security Assessor to understand how organizations identify security risks, assess controls, document findings, and support ongoing security monitoring.

**Project type:** Cybersecurity / Governance, Risk, and Compliance (GRC)  
**Framework:** NIST Risk Management Framework (RMF)  
**Scenario:** Fictional organization – CivicTrack Analytics  
**Platform:** GRC Playground  
**Project status:** Completed – portfolio documentation in progress

---

## Project Objectives

The main objectives of this project were to:

- Understand and apply the seven steps of the NIST RMF.
- Define a system boundary and identify relevant security considerations.
- Categorize an information system based on confidentiality, integrity, and availability.
- Understand security control selection and tailoring.
- Review security assessment evidence.
- Identify and document security weaknesses.
- Understand authorization decisions and continuous monitoring.
- Develop practical GRC documentation skills.

---

## The Seven Steps of NIST RMF

The project covered the following seven steps:

| Step | RMF Activity | What I Learned |
|---|---|---|
| 1 | Prepare | Establishing organizational and system-level context for risk management. |
| 2 | Categorize | Evaluating confidentiality, integrity, and availability requirements. |
| 3 | Select | Selecting and tailoring appropriate security controls. |
| 4 | Implement | Understanding how selected security controls are implemented. |
| 5 | Assess | Reviewing evidence and evaluating whether security controls operate effectively. |
| 6 | Authorize | Understanding security authorization decisions and residual risk. |
| 7 | Monitor | Maintaining ongoing awareness of security risks and control effectiveness. |

## Key Security Findings

During the fictional scenario, I examined several security issues:

| Finding ID | Security Finding | Risk Area |
|---|---|---|
| F-001 | Multi-factor authentication (MFA) bypass on the office network. | Identity and Access Management |
| F-002 | Security baseline configuration was undocumented. | Configuration Management |
| F-003 | Audit events stopped reaching the logging platform after token rotation. | Audit and Accountability |
| F-004 | A critical vulnerability was identified in the reporting framework. | Vulnerability Management |

These findings helped me understand how security weaknesses can affect organizational risk and why remediation, documentation, and continuous monitoring are important.

*Note: These findings belong to a fictional educational scenario. They are not findings from a real organization's security assessment.*

## Learning Outcomes

This project helped me connect cybersecurity governance concepts with practical risk assessment activities.

My main takeaways were:

- Security assessments require evidence, not assumptions.
- Security controls must be evaluated for effectiveness.
- Documented findings help organizations understand and prioritize risks.
- Risk remediation requires accountability and follow-up.
- Authorization decisions involve understanding and accepting residual risk.
- Continuous monitoring is essential because security risks change over time.
